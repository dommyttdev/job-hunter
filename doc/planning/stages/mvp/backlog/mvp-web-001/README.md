# MVP-WEB-001: 監視と求人のWeb画面を提供する

- 状態: Current
- カード状態: Planned
- バックログ索引: [MVPバックログ](../README.md)

## 目的

認証済み利用者が自分のwatchを管理し、関連する求人の現在状態と要約を安全に閲覧できるサーバーサイド画面を提供する。

## Ready判定

- `MVP-AUTH-001`、`MVP-SOURCE-001`、`MVP-DETECT-001`、`MVP-SUMMARY-001`が`Accepted`である。
- Web UIとHTTP境界の未決事項が解消している。
- view modelへ必要な照会契約が利用可能である。

## Accepted判定

- ログイン、ダッシュボード、watch一覧・追加・間隔変更・停止・再開・検索条件修正を操作できる。
- 関連求人のタイトル、現在要約、URL、掲載状態を一覧と詳細で閲覧できる。
- LINE通知状態と必要な次操作を表示できる。
- 他利用者のデータをURL、フォーム、サービス呼び出しから取得・変更できない。

## 確定済み仕様

- FlaskとJinja2によるサーバーサイドHTMLとし、SPAや公開APIを作らない。
- 新規watchの既定間隔は24時間で、12時間も選択できる。
- watchは利用者単位で所有し、同一利用者・サイト・正規化検索URLを重複登録しない。
- 停止中は取得せず、再開時は停止期間を遡らず通知なしで再基準化する。
- 求人canonical HTMLを画面へ直接描画せず、現在要約と機械抽出情報を表示する。

## 受入条件

- [Webバックエンド](../../../../../architecture/web-backend.md)のMVP HTTP境界をFlask test clientで検証できる。
- 未対応URL、重複URL、不正間隔、所有権違反、CSRF違反を安全なエラーとして表示する。
- `NEEDS_ATTENTION`、サイト障害、通知未連携・要対応を識別して表示する。
- 求人一覧と詳細に過去版・過去イベントを表示しない。
- Jinja2の自動エスケープを維持し、不信HTMLを`safe`で描画しない。

## 対象外

- 管理者画面、過去履歴、全文検索、求人比較、応募管理
- SPA、モバイルアプリ、公開API、リアルタイム更新

## 停止条件

- 必要な照会が所有者条件を含むrepository APIで表現できない。
- Web UI文書とHTTP境界が同じ操作について矛盾する。
- 不信HTMLを表示しなければ要件を満たせない変更が必要になる。

## サブタスク構成

依存解消後、共通レイアウト、watch管理、求人照会、状態表示とroute統合を縦断的に分割する。
