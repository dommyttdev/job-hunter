# MVP-OPS-001: MVPを運用可能にする

- 状態: Current
- カード状態: Planned
- バックログ索引: [MVPバックログ](../README.md)

## 目的

完成したMVPの全経路を一つの運用単位として検証し、観測、安全停止、バックアップ、復旧、保守の手順を揃える。

## Ready判定

- 先行7カードがすべて`Accepted`である。
- 配置先の単一ホスト環境とOS側スケジューラーを確定できる。
- 対応サイトと外部サービスの本番設定をsecret管理下で準備できる。

## Accepted判定

- 登録から取得、変更検知、要約、Web表示、LINE配信までの縦断確認が成功する。
- 構造化ログ、処理件数・失敗数・所要時間・キュー滞留から障害を識別できる。
- サイト別安全上限、サーキットブレーカー、取得禁止、Codex利用上限が安全側に作動する。
- DBとsecretのバックアップ・復旧、マイグレーション、再起動、失敗作業再実行の手順を実証できる。

## 確定済み仕様

- 単一ホストでWeb、1スケジューラー、複数ワーカー、同一永続領域のSQLiteを運用する。
- `source_key`、`watch_id`、`job_id`、`work_id`、`event_id`を相関キーとして記録する。
- canonical HTML、認証token、cookie、secret、外部エラー本文を通常ログへ出さない。
- 取得許可を失ったサイトは新規登録と全取得を止め、既存求人状態を維持する。
- 復旧後は通知なしの再基準化を完了してから通常監視へ戻す。

## 受入条件

- MVP機能範囲の完了条件と要件の受入条件を追跡表で確認できる。
- プロセス異常終了、SQLite競合、外部サービス失敗、解析失敗急増、ディスク容量逼迫を試験できる。
- バックアップから別の空環境へ復元し、整合性確認後に処理を再開できる。
- アラートから停止、調査、修正、再基準化、再開までの手順を第三者が実行できる。
- 日常運用と障害対応に必要な未作成文書を`doc/operations/`へ追加する。

## 対象外

- 複数ホスト、高可用性クラスタ、自動水平スケール、24時間有人監視
- SQLite限界が観測される前のDB移行、将来サイトの運用設定

## 停止条件

- 対応サイトの取得許可または外部サービスの本番利用条件を確認できない。
- バックアップ対象とsecretローテーションの責任者・保管先を決められない。
- 重大障害を検知する観測値を既存コンポーネントから取得できない。

## サブタスク構成

依存解消後、デプロイ・設定、観測と安全停止、バックアップ・復旧、縦断受入の単位へ分割する。
