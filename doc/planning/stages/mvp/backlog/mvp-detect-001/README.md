# MVP-DETECT-001: 求人状態の変化を確定する

- 状態: Current
- カード状態: Planned
- バックログ索引: [MVPバックログ](../README.md)

## 目的

取得結果から初回基準化、利用者向け発見、更新、掲載終了、再掲載を冪等に確定し、後続処理へ失われないイベントを渡す。

## Ready判定

- `MVP-FOUND-001`と`MVP-SOURCE-001`が`Accepted`である。
- 変更判定用fixtureが取得アダプターの契約として利用できる。
- データモデルの未決事項が本カードの受入条件へ影響しない。

## Accepted判定

- 変更判定ルールの全テストケースを永続化込みで満たす。
- 求人状態、版、イベント、後続作業を短いトランザクションで一貫して確定する。
- 同じ取得結果の再処理で版・イベント・関連が重複しない。
- 通常時の版数が現在版と直前版へ収束し、処理中参照は保持される。

## 確定済み仕様

- 求人状態イベントは求人単位とし、`DISCOVERED`だけ利用者と求人の組で作る。
- watchは利用者が所有し、同じ利用者の複数watchに同じ求人が含まれても発見を重複させない。
- canonical HTMLだけを比較用ハッシュへ含め、タイトルだけの変化では新版・更新イベントを作らない。
- 明示的な掲載終了は1回、404は間隔を空けた2回連続で掲載終了を確定する。
- 抽出規則更新、watch再開、サイト復旧では通知なしで再基準化する。

## 受入条件

- [変更判定ルール](../../../../../change-detection/change-rules.md)の`CD-001`から`CD-020`を自動テストで満たす。
- 同じ求人が異なる間隔のwatchに含まれても最短間隔で1回取得し、求人状態イベントを共有する。
- 検索結果から消えただけでは掲載終了にしない。
- 429、5xx、解析失敗、取得禁止、サーキット停止中に既存状態を維持する。
- 変更確定と後続作業投入の間でイベントを失わない。

## 対象外

- 要約本文、Web画面、外部通知の生成
- 求人内容の項目別構造化、サイト間名寄せ、利用者向け履歴表示

## 停止条件

- 取得分類から判定規則へ一意に写像できないケースが見つかる。
- 既存データモデルの一意制約で冪等性を保証できない。
- 版削除と処理中参照の整合性をトランザクションで守れない。

## サブタスク構成

依存解消後、スキーマ、基準化・発見、状態遷移、版保持・再基準化の境界で分割可能かを精査する。
