# MVP-NOTIFY-001: LINEダイジェストを配信する

- 状態: Current
- カード状態: Planned
- バックログ索引: [MVPバックログ](../README.md)

## 目的

Googleログイン済み利用者が任意にLINE通知先を連携し、新着・更新・掲載終了を求人単位でまとめた通常・遅延ダイジェストを重複なく受け取れるようにする。

## Ready判定

- `MVP-AUTH-001`、`MVP-DETECT-001`、`MVP-SUMMARY-001`が`Accepted`である。
- LINE Login、Messaging API、公式アカウント、callback・webhookの設定を準備できる。
- チャネル上限と送信結果の分類をfixtureで検証できる。

## Accepted判定

- ログイン済み利用者から開始した1回限りのintentでLINE通知先を本人確認できる。
- 通常枠と遅延枠で対象イベントを求人単位に集約し、1回のダイジェストへまとめられる。
- 静穏時間を守り、チャネル上限時だけメッセージを分割できる。
- 配信の冪等性、再試行、最終失敗、通知OFFを安全に処理できる。

## 確定済み仕様

- LINE Loginは通知先の本人確認だけに使い、JobHunter利用者を新規作成しない。
- 24時間watchは9:00、12時間watchは9:00と21:00を利用者タイムゾーンで通常枠とする。
- 通常枠に間に合わないイベントは遅延対象とし、1時間ごとの別ダイジェストで送る。
- 22:00から翌8:00は配信せず、8:00以降の最初の遅延確認でまとめる。
- 要約最終失敗時もイベント種別、求人タイトル、求人URLを通知する。

## 受入条件

- 同じ求人が同じ利用者の複数watchに該当しても通知項目を1件だけ作る。
- 新着後の更新、新着後の掲載終了、更新後の掲載終了、掲載終了後の再掲載、複数更新を規則どおり集約する。
- 新着・更新・掲載終了を同じ配信時刻の1ダイジェストにまとめ、求人ごとの要約を維持する。
- 同じbatchと通知先の再処理で外部送信を重複させない。
- LINE通知OFF後もGoogle認証、watch、求人関連を維持し、再ON時に過去イベントを送らない。

## 対象外

- LINE以外の通知チャネル、利用者指定の自由な通知時刻、通知履歴画面
- LINE Loginによる会員登録、通知内容への求人HTML埋め込み

## 停止条件

- webhook署名、state、nonce、intentの有効期限を検証できない。
- チャネルAPIの再送安全性または送信結果分類を確認できない。
- 利用者タイムゾーンで通常枠・静穏時間を一意に計算できない。

## サブタスク構成

依存解消後、LINE連携、通知集約・時刻計算、メッセージ生成、配信・再試行を独立して検証できる単位へ分割する。
