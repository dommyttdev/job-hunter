# MVP-FOUND-001-ST01: Pythonプロジェクト骨格を作る

- 親カード: [MVP-FOUND-001](./README.md)

## 成果

依存関係を再現可能に導入でき、空のアプリケーションパッケージに対して静的検査とテストを同じコマンドで実行できるPythonプロジェクト骨格。

## 依存サブタスク

なし。

## 親カードとの関係

後続サブタスクが共有するPython版、依存管理、`src/jobhunter/`、`tests/`、品質コマンドを確定する最初の作業である。

## 変更してよい範囲

- ルートのPythonプロジェクト設定、lockファイル、開発ツール設定
- `src/jobhunter/`の最小パッケージ骨格
- `tests/`の起動確認用テストと共通設定
- セットアップ・品質コマンドを説明する開発文書
- `.gitignore`のPython生成物に関する項目

## 変更してはいけないもの

- DBスキーマ、作業キュー、Flask route、求人監視の業務ロジック
- 認証、取得、要約、通知の外部SDK
- 複数ホストや本番配備だけに必要な依存関係

## 必要な変更

1. 対応Python版を1系列に固定し、Flask、Jinja2、SQLAlchemyと品質ツールの互換範囲を記録する。
2. `src` layoutで`jobhunter`パッケージを作り、暗黙の自動探索なしでimportできるようにする。
3. テスト、lint、format、型検査に採用するコマンドを設定する。
4. 新規環境のセットアップとコマンドを開発文書へ追加する。
5. 空のパッケージを対象とする起動確認テストを追加する。

## 完了条件

- 文書化した手順で依存関係を導入できる。
- テスト、lint、format確認、型検査が成功する。
- 採用版とコマンドが単一の設定ファイルから追跡できる。
- 生成物、仮想環境、secret候補がGit管理対象外である。
- このサブタスクの差分だけでコミットできる。

## 停止条件

- 中核ライブラリが同じPython系列をサポートしない。
- lockまたは再現可能な依存固定を現在の実行環境で生成できない。
- 品質ツール選定が既存の開発方針と矛盾する。

## 返却形式

- 採用したPython・ツール版と判断理由
- 作成・変更したファイル一覧
- 実行した品質コマンドと結果
- 後続サブタスクへ引き継ぐ制約
