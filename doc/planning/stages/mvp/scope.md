# MVP機能範囲

- 状態: Accepted

## 目的

既存の要件と設計から、MVPで実装・検証する境界を明示する。個別の振る舞いは根拠文書を正本とし、この文書では能力単位の範囲だけを管理する。

## 対象範囲

| 領域 | MVPで提供する能力 |
| --- | --- |
| 基盤 | Flask、Jinja2、SQLAlchemy、SQLiteによるWebアプリとバックグラウンドワーカー、永続作業キュー、設定、マイグレーション |
| 認証 | Google OpenID Connectによる登録・ログイン、利用者所有権の強制、アカウント削除 |
| 監視設定 | 対応サイトの検索結果URL登録、12時間・24時間間隔、停止・通知なし再基準化、要対応状態 |
| 求人取得 | 明示登録したサイトアダプターによる全検索ページ巡回、求人IDと詳細URLの抽出、求人固有canonical HTMLとタイトルの保存 |
| 変更検知 | 利用者単位の発見重複排除、求人単位の更新・掲載終了・再掲載、タイトルだけの変更除外、現在版と直前版の保持 |
| 要約 | 現在要約と変更要約、Codex CLIの実行制限、長文分割、最終失敗時のタイトル・URLへのフォールバック |
| Web | 監視設定の管理、関連求人のタイトル・現在要約・URL・掲載状態、通知連携状態の表示 |
| 通知 | Google利用者とLINE通知先の分離連携、新着・更新・掲載終了をまとめた定期ダイジェスト、遅延ダイジェスト、静穏時間、再試行 |
| 運用 | サイト別レート制限と安全上限、サーキットブレーカー、取得許可停止、構造化ログ、メトリクス、障害復旧手順 |

## 対象外

- 求人内容をタイトル以外の項目へ構造化し、検索・集計する機能
- 求人への応募、ログイン必須サイトの取得、異なる求人サイト間の名寄せ
- 利用者向けの過去変更履歴、通知履歴、管理者向け操作画面
- SPA、公開API、モバイルアプリ、LINE LoginによるJobHunterへのログイン
- 複数ホスト、外部メッセージブローカー、SQLite以外のDBを前提とする分散構成
- 対応サイト拡張および運用規模拡張の段階で判断する機能

## 完了条件

- 要件文書の受入条件を、自動テストまたは記録された手動確認で追跡できる。
- 最初に採用する対応サイトについて、契約HTMLを使った取得からWeb表示までの縦断動作が成功する。
- 同一求人が同じ利用者の複数watchに含まれても発見と通知が重複せず、複数利用者間では求人状態を共有できる。
- 通知通常枠、遅延枠、静穏時間、要約フォールバック、再試行を含む縦断動作が成功する。
- 取得禁止、解析失敗急増、安全上限到達時に求人状態を誤って確定せず、安全に停止・再開できる。
- 開発、起動、マイグレーション、監視、バックアップ、復旧の手順が文書化されている。
