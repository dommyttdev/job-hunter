# 0004 検索一覧は新着発見に限定し求人固有コンテンツを保存する

- 状態: Accepted

## 背景

求人サイトの検索結果一覧には、通常のページリンク、form submit、JavaScriptによる「さらに読み込む」など複数の巡回方式がある。一覧巡回は途中で失敗する可能性があり、一覧から求人IDが見えないことだけでは掲載削除と断定できない。

求人詳細ページにはヘッダー、フッター、共通告知、広告、アクセス解析要素など求人とは無関係な領域が含まれる。ページ全体を保存・ハッシュ化すると、共通要素の変更を求人更新として誤検知する。

## 決定

- 検索結果一覧は求人IDと詳細URLの新着発見にだけ使用する。
- 一覧からIDが消えたことを削除判定に使用しない。
- 削除は求人詳細ページの404またはサイト固有の掲載終了表示で判定する。
- 通常リンク、form、load-moreを共通の一覧巡回契約で扱い、巡回完了を判定できない実行から新着を確定しない。
- 詳細ページの生HTMLは一時入力とし、永続化しない。
- サイトアダプターがallowlistで抽出した求人固有領域を正規化し、そのcanonical HTMLだけを保存、SHA-256ハッシュ化、要約入力に使用する。
- 求人固有領域を抽出できない場合は解析失敗とし、空コンテンツやページ全体へフォールバックしない。
- 抽出・正規化規則に`extractor_version`を付与する。

## 代替案

- 一覧差分で削除する方式: 無限スクロールやページングの途中失敗、検索順位上限、サイト障害で誤削除し得るため採用しない。
- 詳細ページ全体を保存して動的属性だけ除去する方式: 共通告知やフッター本文の変更を防げないため採用しない。
- 共通CSS selectorを全サイトへ適用する方式: DOMの意味と境界がサイトごとに異なり、求人情報の欠落や共通領域混入を検知しにくいため採用しない。

## 影響

- JavaScriptで追加表示するサイトにはブラウザー取得器または検証済みページングendpointが必要になる。
- サイト追加には一覧fixtureに加え、求人固有領域、共通領域だけの変更、求人本文変更を表す詳細fixtureが必要になる。
- extractor更新時は既存ハッシュとの単純比較を行わず、移行処理または通知抑止付きの再基準化が必要になる。
- 生HTMLを保持しないため、後から別selectorで再抽出する場合は詳細ページを再取得する。
