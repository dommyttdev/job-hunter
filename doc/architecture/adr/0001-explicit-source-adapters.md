# 0001 求人サイト差異を明示的なアダプターで分離する

- 状態: Proposed

## 背景

求人サイトごとに検索URL、ページネーション、求人IDの位置、詳細URL、掲載終了表示、動的HTML領域が異なる。これらの条件分岐を取得や変更検知へ直接追加すると、サイト追加のたびに既存処理へ変更が波及し、誤検知の回帰範囲が広がる。

プロジェクトのコーディング規約では、実行時探索、リフレクション、動的importを禁止し、型付きインターフェースと明示的登録を求めている。

## 決定

サイト固有処理を型付き`JobSourceAdapter`へ分離する。アダプターはURL適合判定、検索ページ解析、求人ID抽出、詳細ページ状態分類、比較用HTML正規化を担当する。

共通処理はアダプターのポートだけに依存し、具象アダプターはcomposition rootの静的マップへ明示登録する。新規アダプターは共通契約テストとサイト固有HTML fixtureを必須とする。

## 代替案

- 設定ファイルにCSS selectorや正規表現だけを記述する方式: 単純なサイトでは追加が速いが、ページネーション、リダイレクト、掲載終了判定、正規化の差異を表現し始めると独自言語化するため採用しない。
- プラグインの自動探索方式: 外部配布には向くが、参照先が静的に追跡できず、現時点のサイト追加頻度には過剰なため採用しない。
- サイトごとに独立サービスを作る方式: 障害分離は強いが、配備、監視、キュー、共通機能の運用コストが初期規模に対して大きいため採用しない。

## 影響

- サイト追加時の主要な変更先はアダプター、fixture、明示登録、サイト取得設定に限定される。
- 共通の変更検知、データモデル、要約、通知はサイトHTMLを知らずに実装できる。
- 静的登録への1行程度の変更は必要であり、バイナリを再配備する。
- 契約が肥大化しないよう、サイトにしか存在しない機能は共通インターフェースへ安易に追加しない。
