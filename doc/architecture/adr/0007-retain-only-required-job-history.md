# 0007 求人履歴は変更検知と処理中通知に必要な範囲だけ保持する

- 状態: Accepted

## 背景

利用者は過去の変更履歴を求めておらず、求人変更の検知には現在版と直前版があればよい。全HTML版、イベント、要約、配信記録を無期限に保持するとSQLite容量とバックアップ時間が増え続ける。一方、未処理または再試行中の通知が参照する版やイベントを削除すると、安全な再実行ができない。

## 決定

- 求人HTMLは通常、現在版と直前版だけを保持する。
- 未処理または再試行中の通知が参照する版は、処理が完了するまで例外的に保持する。
- イベント、現在要約、変更要約、通知項目、配信記録は処理完了に必要な間保持し、完了後は最新の完了結果だけを残す。
- Web画面に過去の変更履歴を提供しない。
- 求人の現在要約は現在版とともに保持し、変更要約は通知処理の保持期間に従う。

## 代替案

- 全履歴を無期限に保持する方式: 将来の監査や再分析には有利だが、利用者要求がなく保存量が無制限に増えるため採用しない。
- 現在版だけを保持する方式: 保存量は最小だが、変更差分の生成と処理中通知の再試行ができないため採用しない。
- 固定期間で履歴を保持する方式: 分かりやすいが、期間内でも不要なデータを保持し、期間を超えた処理中データを誤削除し得るため採用しない。

## 影響

- 保存量は通常、求人件数に比例する範囲へ収束する。
- 削除処理は通知項目や作業からの参照を確認する必要がある。
- 過去の版を使った再要約や変更履歴の後日追加はできない。
- 将来履歴機能を追加する場合は、この決定を置き換える新しい保持設計とADRが必要になる。
