# 求人サイトアダプター

- 状態: Draft

## 取得対象

利用者が登録した検索結果URLと、検索結果から得た求人詳細URLを取得する。検索結果一覧は新着求人の発見に使用し、削除判定には使用しない。共通処理が受け取る検索結果は、次の値だけを持つ。

| 値 | 内容 |
| --- | --- |
| `source_key` | `atgp`などの求人サイト識別子 |
| `external_job_id` | サイト内求人ID |
| `detail_url` | 絶対URLへ正規化した求人詳細URL |

## 規約・制約

アダプターは次の契約を実装する。名称は概念を示し、実装言語決定時に型として定義する。

| 操作 | 入力 | 出力・責務 |
| --- | --- | --- |
| `supports_search_url` | URL | 許可されたscheme、host、pathかを厳密に判定する。 |
| `normalize_search_url` | URL | 同じ検索条件を表すURLを安定した形式にする。追跡用queryは除去する。 |
| `search_fetch_mode` | なし | `STATIC_HTTP`または`BROWSER`を返す。 |
| `parse_search_page` | 最終URL、rendered HTML | 求人参照、継続要求、正常終了の根拠を返す。 |
| `parse_job_reference` | 詳細リンク | 求人IDを検証・抽出し、詳細URLを正規化する。 |
| `classify_detail_page` | status、最終URL、HTML | `AVAILABLE`、`REMOVED`、`RETRYABLE_ERROR`、`UNEXPECTED`のいずれかを返す。 |
| `extract_job_content` | 詳細ページHTML | 求人固有領域だけをallowlistで抽出する。 |
| `canonicalize_job_content` | 抽出済みHTML | 保存・ハッシュ・要約に使うcanonical HTMLを返す。 |
| `extractor_version` | なし | 抽出・正規化規則の版を返す。 |

継続要求は通常の次ページURL、formから再構成したHTTP要求、ブラウザーのload-more操作を型で区別する。アダプターはHTTP通信、ブラウザー操作、DB、要約、通知へ依存しない純粋な解析処理を基本とし、取得器が継続要求を実行する。アダプター一覧は起動コードの静的なマップへ明示登録し、自動走査や文字列からの動的importは行わない。

## 取得方式・頻度

- スケジューラーは監視対象の`next_run_at`を基に検索取得作業を投入する。
- 検索結果は次ページまたはload-moreがなくなるまで巡回し、一意な求人ID集合を作る。
- 静的ページはHTTP取得器、JavaScriptで追加表示するページはブラウザー取得器を使う。
- form paginationはJavaScript文字列を実行せず、action、method、成功制御を含むinputからHTTP要求を再構成する。
- load-moreは操作前後の求人ID集合を比較し、新規IDが増えない状態が続いた場合は失敗とする。
- 循環要求、最大ページ数、最大操作回数、最大求人件数は安全上限であり、到達時は正常完了ではなく巡回失敗とする。
- 巡回が正常完了した場合だけ抽出した新規求人IDを確定する。部分結果は削除判定にも使用しない。
- 詳細ページは求人単位で取得し、複数の監視対象間で共有する。
- サイト単位の同時実行上限と最小アクセス間隔を全ワーカーで共有する。
- `robots.txt`と利用規約により取得不可、またはログイン必須の場合は監視登録を拒否または停止する。

## データ変換

詳細ページの生HTMLは一時入力とし、永続化しない。アダプターがサイト固有のallowlist selectorで求人に関わる要素だけを抽出し、canonical HTMLへ変換する。保存する`job_revision.content_html`、比較用SHA-256ハッシュ、Codex CLIへの入力は、すべて同じcanonical HTMLを正本とする。

抽出段階では、求人固有コンテナー内の職務、応募条件、勤務地、待遇、会社・募集情報などを含め、次の共通領域を含めない。

- ヘッダー、フッター、グローバルナビゲーション
- 共通のお知らせ、キャンペーン、広告、レコメンド
- ログイン、会員登録、cookie同意、SNS共有
- パンくず、ページング、閲覧履歴、アクセス解析

canonical化では、求人情報の意味を残したまま次を除去または統一する。

- `script`、`style`、コメント、イベントハンドラー
- CSRF token、nonce、アクセス解析ID、ランダムID
- class、styleなど表示専用属性
- URL fragmentと既知のtracking query
- 属性順、改行、連続空白など意味を変えない表現差

抽出対象は「詳細ページ全体から不要要素を引く」のではなく、求人項目の見出しと値を表す要素を個別に足すallowlistとする。選択した要素を文書順に複製し、不要な子要素と属性を除去し、相対URLを正規化して、決定的なHTML serializerでUTF-8へ変換する。同じ入力と`extractor_version`からは常に同じバイト列を得る。

求人固有selectorが0件または必須見出しを満たさない場合は解析失敗とする。空文字や詳細ページ全体へのフォールバックは行わない。抽出・正規化規則には`extractor_version`を付け、版が異なるコンテンツ同士をそのまま更新比較しない。

## エラー・再試行

| 状況 | 扱い |
| --- | --- |
| タイムアウト、DNS、接続切断 | 指数バックオフとjitterで再試行 |
| HTTP 429 | `Retry-After`を優先し、サイト全体の取得を抑制 |
| HTTP 5xx | 上限付き再試行 |
| HTTP 401、403 | 削除扱いにせず、設定・アクセス制限の異常として停止候補 |
| HTTP 404 | 詳細ページでは`REMOVED`、検索ページでは監視設定異常 |
| HTTP 200の掲載終了ページ | アダプターが明示的なマーカーで`REMOVED`と判定 |
| 一覧巡回の途中失敗・安全上限到達 | 部分的な新着を確定せず、一覧全体を再試行 |
| 求人固有領域が抽出不能 | 削除や空更新にせず`UNEXPECTED`として隔離・通知 |
| DOM解析失敗、想定外リダイレクト | 削除扱いにせず`UNEXPECTED`として隔離・通知 |

HTTPリダイレクトごとに遷移先hostを検証し、内部ネットワークや未許可hostへのアクセスを拒否する。レスポンスサイズと展開後サイズに上限を設ける。

## 監視

- 取得成功率、status code、応答時間、レスポンスサイズ
- 検索ページ数、load-more操作数、抽出求人件数、ID解析失敗件数、巡回終了理由
- 詳細分類ごとの件数、求人固有領域の抽出サイズ、ハッシュ変更率
- 429件数、サイト別キュー滞留時間、最終成功時刻
- アダプターの`UNEXPECTED`増加をHTML構造変更の兆候として警告

## 新しいサイトを追加する手順

1. 利用規約、robots.txt、認証要否、許容アクセス頻度を確認する。
2. URL許可規則とサイト単位の取得設定を追加する。
3. `JobSourceAdapter`の具象実装を追加する。
4. 検索1ページ、全ページング方式、詳細、有効、掲載終了、構造変更のHTML fixtureを追加する。
5. 詳細fixtureで共通領域だけの変更はハッシュ不変、求人本文の変更はハッシュ変化となることを検証する。
6. 共通契約テストにアダプターを明示登録する。
7. 起動コードの静的アダプターマップへ追加する。
8. ステージングで低頻度監視し、抽出件数と誤更新率を確認して有効化する。
