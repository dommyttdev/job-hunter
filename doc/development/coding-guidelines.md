# エージェント向けコーディング規約

## 最優先：静的解決可能性

- リフレクションを禁止する。型、依存、呼び出し、登録を静的に追跡可能にする。
- 実行時探索、文字列による型・関数解決、自動走査・登録、Service Locator、動的importを使わない。
- 明示的import、コンストラクタDI、型付きインターフェース、明示的登録、静的マップ、コード生成を使う。
- DRYより優先する。IDEの参照検索またはテキスト検索で実装まで追跡できること。

## 設計

- KISS・YAGNI：最小で単純な設計とし、未要求の拡張を作らない。
- DRY：知識の重複を避ける。偶然似たコードを早期に抽象化しない。
- 驚き最小限：名前、API、挙動を予測可能にする。暗黙の副作用を避ける。
- 単一責任・関心分離・高凝集・疎結合を保つ。
- 依存性逆転・インターフェース分離を行い、継承より合成を優先する。

## 実装・品質

- 外部入力を境界で検証し、副作用を局所化する。
- エラーを握り潰さず、再試行処理は冪等にする。
- コメントは判断理由・制約を書く。
- 振る舞いをテストし、不具合修正には再発防止テストを加える。
- 機密情報をコード・ログへ出さず、性能は計測後に最適化する。
- 既存規約に従い、タスク外変更・不要な依存・抽象化を加えない。
