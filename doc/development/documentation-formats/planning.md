# 計画

計画文書は、要件・設計を実装可能な順序と作業単位へ変換します。要件や設計の内容を複製せず、根拠となる正本文書へリンクします。

## 計画索引

```markdown
# 計画

計画文書の目的を1文で記載する。

## 現行段階
## 文書一覧
## 運用ルール
```

## 段階計画

```markdown
# {段階名}計画

- 状態: Planning | Current | Completed | Archived

## 目的
## 開始条件
## 完了条件
## 文書一覧
```

段階の対象範囲、実装順序、バックログは別文書を正本とし、段階READMEへ要約を重複させません。

## バックログ索引

バックログ索引をカードID、概要、永続状態、依存、根拠の正本とします。

```markdown
| ID | 概要 | 永続状態 | 依存 | 根拠 |
| --- | --- | --- | --- | --- |
```

永続状態は次の5種類だけを使用します。

| 状態 | 意味 |
| --- | --- |
| `Unrefined` | 内容と境界が未整理 |
| `Planned` | 目的、範囲、依存を整理済み |
| `Ready` | 単独で着手し、完了判定できる |
| `Blocked` | 判断または依存の解消待ち |
| `Accepted` | 実装、検証、統合が完了 |

状態別ディレクトリは作らず、状態変更でカードを移動しません。

## 親カード

```markdown
# {CARD-ID}: {タイトル}

- 状態: Current
- カード状態: Unrefined | Planned | Ready | Blocked | Accepted
- バックログ索引: [リンク]

## 目的
## Ready判定
## Accepted判定
## 確定済み仕様
## 受入条件
## 対象外
## 停止条件
## サブタスク構成
## 根拠文書
```

## サブタスク

```markdown
# {CARD-ID}-ST{NN}: {タイトル}

- 親カード: [リンク]

## 成果
## 依存サブタスク
## 親カードとの関係
## 変更してよい範囲
## 変更してはいけないもの
## 必要な変更
## 完了条件
## 停止条件
## 返却形式
```

サブタスクは独立して実装、検証、コミットできる場合だけ作ります。小さなカードは`README.md`だけで完結させます。

## IDと配置

- カードIDは`<段階>-<領域>-<3桁連番>`とする。例: `MVP-SOURCE-001`。
- カードディレクトリはIDを小文字化した名前とする。例: `mvp-source-001/`。
- サブタスクは`<card-id>-st<2桁連番>-<短い英語名>.md`とする。
- 完了カードは現行段階内に残し、段階全体の完了時に段階ディレクトリごと`stages/archive/`へ移す。
